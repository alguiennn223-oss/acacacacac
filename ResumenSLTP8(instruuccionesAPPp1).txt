7. PLAYER RECORD PRINCIPAL
El Player Record principal mide EXACTAMENTE:
0x138 = 312 bytes.
Comienza en:
0x7C
Fórmula:
player_offset = 0x7C + (player_index * 0x138)
Prueba:
13566 * 0x138 + 0x7C = 0x0040960C
Cuando había 13567 jugadores:
Actual end:
0x00409744
Diferencia:
0x138
Por lo tanto se comprobó físicamente que agregar un record adicional de
0x138 funciona.

Los jugadores creados desde PES:
* aparecen con IDs especiales negativos.
* pueden existir sin nombre de camiseta/comentarista personalizado.

* pueden ser asignados a un equipo.

resolverlos/asignarlos a un equipo.
Esto demuestra que PES puede aceptar un jugador creado con información mínima.
Por eso la investigación debe comparar un jugador creado por PES que funciona
contra nuestro clon que PES rechaza.

30. REGLA DE ASIGNACIÓN DE PLAYER IDS
PES no permite que el mismo Player ID esté en dos equipos simultáneamente.
Ejemplos observados:

se movió de Team 1493
a Inter 1950-99
? dejó Team 1493.
Matthäus:
se movió de Inter 1950-99
a Brasil 1958
? dejó el equipo anterior.
Por lo tanto:
Un Player ID = una asignación de equipo.
Consecuencia para la app:
NO podemos simplemente poner Player ID 9087 en el nuevo equipo.
Tenemos que clonar:
9087
? nuevo ID
? nuevo equipo.
Esto es fundamental para el diseño final.

    "w"
);

    fprintf(
        f,
        "SEARCHING FOR PLAYER ID 0x%08X\n\n",
        target
    );

    for (uint32_t pos = 0;
         pos + 4 <= d->fileHeader->dataSize;
         pos++)
    {
        uint32_t value =
            d->data[pos] |
            (d->data[pos + 1] << 8) |
            (d->data[pos + 2] << 16) |
            (d->data[pos + 3] << 24);

            fprintf(
                f,
                "FOUND #%d : 0x%08X\n",
                found + 1,
                pos
            );

            found++;
        }
    }

    fprintf(
        f,
        "\nTOTAL FOUND: %d\n",
        found
    );

    fclose(f);
}
